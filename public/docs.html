Get started locally

# one time
git clone https://github.com/Johnnyohay/anu.git && cd anu
npm ci

# refresh the data (all free, no API keys)
npm run collect        # defense news + today's brief
npm run housing        # Zillow prices, rents, forecast, inventory; Freddie Mac rates; housing news
npm run videos         # new videos and Shorts from config/videos.yaml

# apply config/*.yaml and rebuild the JSON the pages read
npm run build:api

# look at it
npx serve public       # open http://localhost:3000 (Docs tab: /docs.html)
npm run app            # Ask ANU with a free local model (see README)

Push to main and the GitHub Action does the same every morning at 10:00 UTC and publishes the site. A push that only changes config/ or public/ redeploys within a few minutes.

Architecture

Collectors pull free public sources into data/ (committed, so history builds up). build-api checks your YAML, adds your custom attributes, and writes static JSON to public/api/v1/. Every page and Ask ANU read only that JSON. There's no server or database, and nothing costs money.

Custom attributes

A custom attribute is a new metric you define in YAML as a formula over the numbers ANU already has for every metro. You don't write any page code. Each one automatically:

  • appears in the housing map's Color by menu, with its own legend;
  • is aggregated to states (median, mean, min, max, sum or count of the state's metros) to shade the map behind the dots;
  • becomes a sortable column in the rankings if column: true;
  • shows in each metro's panel, and reaches Ask ANU (in get_metro and rank_metros results as custom).
# config/anu.yaml → housing.attributes
- id: rentBurden                     # letters and digits; used in URLs and the API
  label: Rent as % of a $90k income
  formula: rent * 12 / 90000 * 100   # + - * / ( ), numbers, min() max() abs() round()
  format: percent                    # money kmoney signedMoney percent percent2 signedPercent number
  color: seq                         # seq = one hue low→high · div = two hues around zero
  aggregate: median                  # how metros roll up to a state
  column: true                       # add to the rankings table
  higherIsBetter: false              # default sort direction

Fields a formula can use: . A metro missing any field in the formula gets no value and shows gray. Formulas are read by ANU's own small calculator (src/config.ts), never run as code.

Video channels

The Watch tab and the housing Shorts strip come from config/videos.yaml. To add a channel, open it on YouTube, view the page source, search for externalId (starts with UC) and add a line. Any new topic name becomes a filter on the Watch tab.

ChannelTopicChannel id

ANU embeds and links videos and never downloads them. TikTok and Instagram have no free public feeds and don't allow scraping, so they aren't collected.

Adding features in code

  1. A switchable page feature: add my.feature: true under flags:, then in the page: if (ANU.flag(CFG, "my.feature")) renderMyFeature();. Add a row to FLAG_INFO in docs.html so it's described here.
  2. A new setting: add it to the schema in src/config.ts (it's validated and published in config.json automatically), then read it from CFG in the page.
  3. A new built-in metro metric (from a new data source): compute it in collectMarket() in src/housing.ts, add it to the Metro type and SORTS in src/housing-kb.ts, to FORMULA_FIELDS in src/config.ts, and to METRICS in housing.html.
  4. A new tab: copy videos.html as a starting point (it loads desk.css and desk.js), add it under desks:, and publish its data from src/build-api.ts.
  5. A new Ask ANU lookup: add a query in src/housing-kb.ts or src/kb.ts and a tool in src/tools.ts; the local app, the CLI (src/kb-cli.ts) and the Claude Code agent (.claude/agents/anu.md) can all use it.
